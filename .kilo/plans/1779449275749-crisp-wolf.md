# Plan: CSS Mobile-First Layout Revision

## Goal

Revise `styles.css` so the entire app is **100vw × 100vh, not scrollable**, with exact, percentage-based height allocations:
- **Header** — 10%
- **Player Dashboard** — 35%
- **Stations List** — 50%
- **Footer** — 5%

Player dashboard internals:
- CRT display — 15%
- Soundbar module — 70%
- Ctrl-row — 15%

Station list:
- List button header — 10%
- Scrollable station list — 90%

All sizing (fonts, buttons, everything) must use responsive units — no raw `px` values for layout dimensions or typography.

## Rationale — `dvh` vs `vh`

`dvh` (dynamic viewport height) tracks actual browser chrome on mobile — when the address bar hides/shows, `vh` is static and causes layout jumps; `dvh` adjusts in real time. This keeps the 10% + 35% + 50% + 5% = 100dvh total accurate across all device sizes and chrome states.

## Preserved / Must Not Break

- **Soundbar visualiser** (`useAudioBars` hook + `SoundBar` component): JSX must remain untouched.
- **PlayerDashboard / StationList / App.jsx JSX structure**: no function/component additions or removals.
- All class names, IDs, and event signatures in JSX must stay identical.
- EPG modal overlay behaviour, station click → `selectStation`, play/pause, volume logic all unchanged.
- `PlayerDashboard.jsx` internal class names: `.crt-display`, `.soundbar-module`, `.ctrl-row` must remain; only CSS inside them changes (sizing to %).
- Selectors like `:contains("STANDBY")` / `:has(.is-active)` etc. must continue to work after changes.

## Implementation Steps

### Step 1 — Opening section (body / #root / .container)

**`body` (L49):** Replace `min-height: 100vh` → `height: 100dvh;`.  
Add `overflow: hidden;` to prevent any page scroll (both mobile and desktop).

**`#root` (L83):** `max-width: 520px; margin: 0 auto;` — unchanged. Root centers the app horizontally but must not add its own height constraint.

**`.container` (L89):** Replace `min-height: 100dvh` → `height: 100dvh;`.  
Remove the `gap: 10px` — children now own exact `dvh` shares that sum to 100dvh, so any gap would overflow the viewport.  
Set `width: 100%; overflow: hidden;`.  
Set `display: flex; flex-direction: column;` — all four children use `flex: 0 0 Xdvh` (non-shrink, non-grow, fixed-basis) so there is no gap enforcement and no overflow.

### Step 2 — Header (.chassis-header L101)

Add:
```css
height: 10dvh;
flex: 0 0 10dvh;
```
Remove any inherited `min-height`. Internal structuring responds to 10dvh.

### Step 3 — Player Dashboard (.player-dashboard L195 + inner sections)

Add to `.player-dashboard`:
```css
height: 35dvh;
flex: 0 0 35dvh;
overflow: hidden;
display: flex;
flex-direction: column;
```

Inner children are three direct children of `.player-dashboard`, all using `flex: 0 0` percentages so they fit exactly inside 35dvh:

| Inner element | Flex share |
|---|---|
| `.crt-display` | `flex: 0 0 15%` |
| `.soundbar-module` | `flex: 0 0 70%` |
| `.ctrl-row` | `flex: 0 0 15%` |

**`.soundbar-bars` height (L415):** Replace
```css
/* Before: */
height: clamp(100px, 28vh, 200px);
/* After: — fits inside 70% of 35dvh = 24.5dvh; clamps to reasonable pixel floor/ceiling */
height: clamp(18px, calc(50vh - 15dvh), 120px);
```
This keeps the visualiser proportional but never exceeds what the module can contain.

**`.ctrl-row` (L506):** Add `overflow: hidden` to prevent any child from spilling beyond the 15% slab. The three `.ctrl-left` bars become 0 height / invisible if needed — they are purely flex-balancing helpers.

### Step 4 — Station List (L753-784 + comp/StationList.jsx)

`StationList` root element becomes the **50dvh** flex-child of `.container`.

**`comp/StationList.jsx` change** — restructure the single root `<div className="station-list">` into a wrapper + two inner slabs. No new props, no event-signature change:

```jsx

```

Existing `.station-item` styles are untouched — they live on the rendered `<div className="station-item">` inside `StationItem.jsx`, not on the wrapper.

**CSS:**

### Step 7 — Media-query refinement (L1413-1448)

Retain the existing width breakpoints `(min-width: 390px / 480px / 768px)` — they set font sizes and horizontal padding.

Add **height-cap** breakpoints below them so inner elements don't overflow a short mobile viewport:

```css
@media (max-height: 520px) {
  .chassis-header .header-model { font-size: 0.48rem; letter-spacing: 0.15em; }
  .chassis-footer               { font-size: 0.42rem; padding: 4px 12px; }
  .ctrl-row                     { gap: 6px; }
  .push-btn                     { min-width: clamp(28px, 10dvh, 38px); min-height: clamp(28px, 10dvh, 38px); }
}

@media (max-height: 400px) {
  .crt-display       { padding: 6px 8px; }
  .soundbar-bars     { height: clamp(12px, 6dvh, 40px); }
  .push-btn.skip-btn { min-width: clamp(22px, 8dvh, 32px); min-height: clamp(22px, 8dvh, 32px); }
}

@media (min-width: 900px) {
  .soundbar-bars { justify-content: center; }
}
```

These are additive; `min-width` breakpoints run first, then height overrides kick in only when both conditions match.

4. Station rows scroll vertically inside the bottom 90% panel; `overflow: auto` is patchy on iOS so confirm `-webkit-overflow-scrolling: touch` is carried to `.station-list-inner` if needed
