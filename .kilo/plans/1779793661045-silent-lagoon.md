# Plan: Collecting EPGs from Radio Stations

Objective
- Define a practical, low-friction process to collect Electronic Program Guides (EPGs) from every radio station so they can be ingested by our system.

Assumptions
- Stations control their own websites and can host static files or expose endpoints.
- We want an approach that balances station effort, reliability, and automation.
- We will provide tooling and validation to reduce support load.

Requirements (non-technical)
- Clear spec and a ready-to-use JSON template to send to stations.
- Validation tooling and onboarding documentation.
- A fallback ingestion method for stations that cannot self-host.

Recommended approach (summary)
- Primary: Ask each station to host a single JSON feed at a stable URL and provide that URL to us.
- Provide a strict JSON schema, an example file, and minimal hosting/CORS/cache guidance.
- Offer alternatives: XMLTV (industry standard), published Google Sheet / Airtable JSON, or a push API/FTP upload if they prefer not to host publicly.
- Provide a hosted option where we host the feed for them if they cannot host it.

Why this approach
- A hosted JSON feed is simple for most web-savvy stations, easy to validate, easy to fetch, and supports caching headers for scale.
- XMLTV is compatible with many EPG tools — accept it if a station already provides it.
- Push APIs/FTP/SFTP avoids public hosting and fits stations with stricter security policies.

JSON feed spec (recommended minimal schema)
- Root object: { channel_id, channel_name, timezone, language, programs: [] }
- Program object: { id?, title, description?, start: ISO8601, end: ISO8601, categories?: [], image?: url, episode?: string }
- Example program times: "2026-06-01T08:00:00+02:00"
- Timezones: prefer explicit offsets or IANA tz values in channel-level timezone field; our ingestion treats times as timezone-aware.

Headers & hosting guidance
- Content-Type: application/json; charset=utf-8
- Cache-Control: max-age=60 (or as agreed), and ETag or Last-Modified for efficient polling
- Support CORS if the feed may be requested client-side (Access-Control-Allow-Origin: *)
- Use HTTPS and a stable URL (avoid query strings that change frequently)

Validation and rollout
- Provide a JSON Schema file and an online/CLI validator we run against each submitted URL.
- Stages for onboarding each station:
  1. Send spec + example JSON + checklist
  2. Station implements and provides URL (or selects alternative)
  3. We run validation; report errors back with actionable fixes
n  4. Once valid, mark station as active and schedule regular polling

Polling frequency & failures
- Default poll every 5–15 minutes for near-real-time schedules; hourly for low-change schedules.
- On fetch failures: exponential backoff, mark stale after configurable threshold (e.g., 48h), and fall back to last-known schedule or display "no EPG available".

Alternatives (details)
- XMLTV (XML): Accept if station already exposes XMLTV; many EPG toolchains use this.
- RSS/Atom with schedule entries: Acceptable if they include start/end datetimes.
- iCalendar (VEVENTs): Works but less common for hourly program schedules.
- Hosted-by-us: Station provides schedule via a simple form or spreadsheet; we host JSON under a subdomain or path.
- Push API: Stations POST JSON to our endpoint (auth via API key). Good for stations that update frequently and prefer push.
- SFTP/CSV: Stations drop files to an SFTP server we control; we ingest and convert.

Tradeoffs
- Requiring stations to host JSON reduces our hosting burden but increases station work.
- Hosting feeds for stations increases our operational load but reduces friction and will likely increase adoption.
- XMLTV compatibility improves interoperability with existing tools but adds parsing complexity for us.

Onboarding materials to prepare (deliverables)
- One-page spec (JSON schema + example)
- Example JSON file and XMLTV sample
- Validation tool (web/CLI) and error messages guide
- Short onboarding checklist and email template for outreach

Automation & monitoring
- A registry of station feeds with status (validated, last-fetched, last-error, stale flag)
- Health checks and alerting for repeated validation or fetch failures
- Automated conversion pipeline to normalize all accepted formats into our canonical JSON representation

Minimum viable rollout plan
- Week 0: Create spec, validator, and templates
- Week 1: Pilot with 5–10 friendly stations — include one station we host for
- Week 2–4: Iterate on validator and docs, onboard more stations
- Ongoing: Offer hosted/push alternatives and monitor adoption

EPG Maker UI - Implementation Plan

Goal
- Provide a simple, intuitive web page under /epg_maker that lets radio staff build a valid EPG with an interactive UI and download the resulting JSON file for hosting on their domain (or upload to /public/EPGs for local testing).

Constraints & notes
- Project already uses React + Vite (package.json). Implement the UI as a small React app reusing existing dependencies.
- You requested the page live at /epg_maker in the repository root and for the directory to be autonomous so it can be moved later to another repo. The implementation will live at /epg_maker at the project root and include its own package.json, schema, and build outputs so it can be extracted as a standalone module.
- This is a plan-only step; no files will be created until you approve.

High-level features
- Channel metadata form: channel_id, channel_name, timezone (IANA), language, optional logo URL.
- Program editor: add/edit/delete program entries with fields: title, description, start (datetime-local), end (datetime-local), categories (tags), image URL, optional episode/id.
- Program list with drag-to-reorder and bulk-add (CSV import) options.
- Live validation against the canonical JSON Schema (use existing scripts/validate-epgs.js as reference) with inline error messages.
- Import existing EPG JSON and pre-fill the editor.
- Download button to produce a validated JSON file (filename pattern: epg-<channel_id>.json) and optionally copy to clipboard.
- Preview panel showing canonical JSON and a human-readable schedule table.
- Accessibility: keyboard-first forms, labels, aria attributes.

UX flows
1. Create new EPG: staff fills channel metadata, adds programs, runs validator (automatic or on-demand), then clicks Download to save JSON.
2. Edit existing EPG: Click Import, upload JSON, edit, validate, download updated file.
3. Quick-export: Small "one-day" wizard to create a daily schedule from repeated program blocks.

Directory & file layout (implementation)
- /epg_maker/  (root of repository; autonomous module)
  - index.html (mount point for SPA)
  - src/
    - main.jsx (React entry)
    - App.jsx
    - components/
      - ChannelForm.jsx
      - ProgramEditor.jsx
      - ProgramRow.jsx
      - ProgramList.jsx
      - ImportExport.jsx
      - Validator.jsx (wraps validation logic)
    - schema/epg.schema.json (canonical schema for client validation)
    - utils/epg-utils.js (serialize/normalize/timezone helpers)
    - styles.css
  - scripts/
    - validate-epgs.js (optional copy or wrapper to reuse server validation)
  - package.json (module-scoped; allows independent install/build)

Validation
- Client-side validation will use AJV (user choice confirmed). The schema will be placed at schema/epg.schema.json and the UI will validate locally before download.
- Reuse existing server-side validator script: scripts/validate-epgs.js can be adapted to use the same schema for CI or server-side checks.

Download / Export behavior
- When user clicks Download:
  - Run final validation; if valid, prepare JSON with consistent keys and timezone-normalized ISO timestamps.
  - Trigger file download using a Blob and anchor download.
  - Filename: epg-<channel_id>-<YYYYMMDD>.json (optional date suffix)

Integration with existing /public/EPGs
- Document how station staff can upload the generated file to their domain's /public/EPGs or host wherever they prefer.
- Optionally add a small helper: a ready-to-copy HTTPS upload checklist (preferred URL path, headers to set: Content-Type, Cache-Control, CORS) shown after download.

Testing & QA
- Manual test checklist: create/import/validate/download, CSV import, timezone edge cases, overlapping programs detection, very large program lists.
- Run npm run build in /epg_maker to ensure bundling works and assets can be deployed under /epg_maker.

Accessibility & internationalization
- Provide labels and placeholders; support RTL layouts if necessary.
- Keep time entry in local timezone with explicit IANA option for advanced users.
