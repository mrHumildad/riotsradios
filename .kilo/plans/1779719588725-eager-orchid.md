**Date**: 2026-05-25

## 3. Recommended Approach

### Core implementation (minimal surface)
Add a `useEffect` inside `StationList` that reacts to `currentStationIndex` changes:

```jsx
// comp/StationList.jsx
import React, { useEffect, useRef } from 'react'
...
function StationList({ stations, currentStationIndex, ... }) {
  const listRef = useRef(null)

  useEffect(() => {
    if (currentStationIndex == null) return
    const container = listRef.current
    if (!container) return

    const itemEl = container.querySelector(`#station-${currentStationIndex}`)
    if (itemEl) {
      itemEl.scrollIntoView({
        behavior: 'smooth',
        block: 'center',   // per user clarification
        inline: 'nearest'
      })
    }
  }, [currentStationIndex])

  return (
    <div className="station-list-wrapper">
      ...
      <div className="station-list-inner" ref={listRef}>
        {stations.map(...) }
      </div>
    </div>
  )
}
```

### Why this location & technique
- **StationList** owns the scroll viewport → natural place for scroll side-effect
- `useEffect` + `[currentStationIndex]` guarantees it runs after the new `isActive` classes have been applied
- `querySelector` scoped to the ref (cleaner than global `getElementById`)
- `scrollIntoView(..., block: 'center')` is the exact browser primitive for "make this item visible + prominent"
- Re-uses the same `behavior: 'smooth'` pattern already proven in EPGModal
- Works for **all** change sources automatically (no need to thread "source" info from logic/App)
- Harmless on mount (index 0 is visible) and on direct clicks (nearest/center will adjust or no-op)

### Optional CSS polish (recommended)
Add to `.station-list-inner` in `styles.css:1055`:
```css
scroll-behavior: smooth;   /* fallback for any future non-JS scrolls */
```
(This does not conflict with the JS `behavior` override.)

No other CSS changes needed.

### No changes required in:
- `logic.js` (keep pure radio state)
- `App.jsx` (no new props or wiring)
- `StationItem.jsx` (no new props/refs)
- `PlayerDashboard.jsx`
- `stations.js`

## 5. Edge Cases & Mitigations

| Case | Risk | Mitigation |
|------|------|------------|
| Rapid next/prev (hold arrow) | Multiple overlapping smooth scrolls | Browser coalesces; effect runs on each state update but `smooth` anims are short (~0.3-0.5s). Acceptable for radio tuner. If jitter reported later, add a 120ms debounce (simple `setTimeout` + cleanup). |
| Index 0 or last item | Centering may hit scroll limits | `scrollIntoView` gracefully stops at edges. Good UX. |
| Very short viewport (mobile portrait) | Item still partially cut off? | `block: 'center'` + existing min-height ensures at least the item is centered as much as possible. Test on small screens. |
| EPG modal open + station change? | (Can't happen — arrows are swallowed by modal handler) | `App:52-55` blocks station keys when modal present. Safe. |
| Initial load / hydration | Scroll before paint | `useEffect` runs after paint — correct. |
| Station list not yet in DOM (theoretical) | Ref null | Guard `if (!container)` — no-op. |
| Future dynamic station list length | ID collision? | IDs are `station-${index}` based on array position (stable for lifetime of app). Fine. |
