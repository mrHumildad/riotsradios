# Station List: Visual Distinction for Selected-but-Stopped vs Playing

**Plan ID**: 1779720935159-swift-cabin  
**Date**: 2026-05-25  
**Status**: Ready for implementation  
**Goal**: When a station is selected in the list but not currently playing (i.e. stopped via the stop button), the stations list UI must visually indicate it. Make all elements that are currently rendered green (for the playing state) use red instead when the item is the selected station but audio is stopped. Do not touch any other colors in the codebase.

## 2. Requirements & Constraints (from user + codebase)

- **Exact visual rule**: every element currently green under `.playing` must become red (using `--red-live`) under the new "selected but stopped" state.
- **Do not touch any other colors**:
  - Leave all amber, cyan, green-active vars and usages unchanged.
  - Do not alter dashboard, EPG, header, buttons, etc.
  - Only add new rules in the station-item section of `styles.css`.
- Use existing CSS var `--red-live` (#ff2e2e) for the red (user preference).
- Class name for the new state: `'selected'` (user preference).
- Scan-line animation (`::after`) **exclusive to playing** (user preference).
- Hover: selected-stopped items must keep red border on hover (consistent with playing keeping green) (user preference).
- Play indicator symbol:
  - Playing: keep `▶` (green)
  - Selected-but-stopped: use **different symbol** `■` (red) (user preference)
  - Unselected: keep `▷`
- Keep behavior identical: clicking a stopped-selected item starts playback (green), togglePlay while selected flips between green/red.
- Initial load (index 0, !playing) must now render as red-"selected".
- No new animations, gradients, or text-shadows beyond mirroring the existing green ones with red.
- No changes to `logic.js` DOM hacks, audio logic, or prop drilling beyond the two list components.
- No impact on EPG, keyboard, remote controls, or responsiveness.

## 3. Recommended Approach

### Minimal surface, React-driven (no new state)
- Add a second prop `isSelected={currentStationIndex === index}` in `StationList`.
- Keep the existing `isActive` prop exactly as-is (it means "is currently playing").
- In `StationItem`:
  - Accept `isSelected`.
  - Compute class: `station-item` + ` playing` (if isActive) + ` selected` (if isSelected && !isActive).
  - For the play-ind symbol: ternary on three states (`▶` / `■` / `▷`).
- In `styles.css`: after the entire `.playing` block, add a parallel `.selected` block that:
  - Mirrors border, background tint (red version), box-shadow.
  - Targets `.selected .station-num`, `.selected .play-ind`, `.selected::before`.
  - Explicit `.selected:hover` rule to keep red border (so it wins over the earlier hover rule).
  - **No** `::after` scan-line rule for `.selected`.
- All styling uses only `--red-live` and existing panel vars — no new tokens.
- Result: purely presentational; `currentStationIndex` + `isPlaying` already give us the three states.

This follows the exact pattern of the previous scroll fix (tiny, localized, no logic changes).

## 5. Edge Cases & Mitigations

| Case | Risk | Mitigation |
|------|------|------------|
| Initial load (index 0, !playing) | Was invisible; now must be red "selected" | React render on first mount will apply `.selected` via the new prop |
| Click stopped-selected item | Must start playback and flip to green | `selectStation` already does this; only UI class changes |
| Toggle stop while playing | Must flip current item from green to red | `isPlaying` state change → re-render with `isActive=false` + `isSelected=true` |
| Rapid next/prev while some are stopped | Old item must lose any highlight | React re-renders all items with fresh props each time; DOM hack in logic only removes 'playing' (harmless) |
| Hover a selected-stopped item | Must not lose red (per user) | Explicit `.selected:hover` rule after the base hover rule |
| EPG badge / WEB link on a selected item | Must not be affected | They already sit in `.station-aside`; no color rules target them under `.playing`/`.selected` |
| Font support for '■' | Monospace stencil might render poorly | '■' (U+25A0) is basic geometric shape, widely supported; fallback is still a filled block. If rendering issue appears in testing we can switch to '●' or '▪' with one-line edit. |
| CSS cascade / specificity | Red rules must win exactly like green rules | Placement after `.playing` + explicit hover override guarantees it |

## 6. Verification / Testing Plan

**Manual test matrix** (run `npm run dev`, use mouse + keyboard + stop/play button):

1. Fresh load:
   - CH 01 shows red `■` (num red, left border red, right marker red, no scanline).
2. Click CH 01 (or press play):
   - Instantly becomes green `▶`, scanline appears, all elements green.
3. Press stop (dashboard):
   - Same item flips to red `■` (no scanline).
4. Click CH 03 while CH 01 is stopped:
   - CH 01 loses all highlight (back to amber-dim).
   - CH 03 appears green `▶` with scanline.
5. Stop CH 03 → CH 03 red `■`.
6. While CH 03 red, click it again → green.
7. Use keyboard arrows / next/prev buttons:
   - New item always gets correct color (green if we just selected via arrows, since arrows call selectStation which auto-plays).
8. Hover tests:
   - Hover red-selected → border/marker stay red (never amber).
   - Hover green-playing → stays green.
   - Hover normal item → amber (unchanged).
9. EPG open + live show on a red-selected item: only the show title uses its own red (live dot) — station row itself stays the selected red.
10. Resize / scroll while in mixed states: no breakage.
11. Console: zero errors or warnings.

**Visual acceptance**:
- Red must be exactly the same "weight" as the current green (bright, with glow).
- No accidental amber bleed on selected items.
- '■' symbol must be clearly visible and centered in the 20px play-ind slot.
- Overall aesthetic stays "factory dashboard" — red now means "armed/selected, ready to play".

**If symbol '■' looks off**:
- One-line fallback in StationItem: change to `'●'` (or `'▪'`).
