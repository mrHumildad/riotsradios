- **Git history**: 14 commits, no formal versioning or release tags

## Recommended Approach: Changeset with Standard SemVer

### Strategy Overview
For production releases starting at 1.0.0, I recommend **Changeset** for automated versioning with changelogs:

1. **Version format**: Standard semver `v[major].[minor].[patch]`
   - Examples: `v1.0.0`, `v1.0.1`, `v1.1.0`
   - Patch for bug fixes, minor for features, major for breaking changes

2. **Automation**: Changeset tracks changes via markdown files and auto-generates changelogs

### Implementation Steps

#### 1. Install changeset
```bash
npm install -D @changeset/cli
npx changeset init
```

#### 2. Update package.json scripts
```json
{
  "scripts": {
    "changeset": "changeset",
    "version": "changeset version",
    "release": "changeset version && npm run build && npm run deploy && git push --follow-tags",
    "postversion": "git add . && git commit -m 'Version packages'"
  }
}
```

#### 3. Workflow
1. Make changes to your app
2. Run `npx changeset` to document what changed (select: patch/minor/major)
3. Commit the changeset file
4. Run `npm run release` to:
   - Bump version in package.json
   - Generate/update CHANGELOG.md
   - Create git tag
   - Deploy to GitHub Pages
   - Push everything

### Benefits
- **Automatic changelogs** - generated from your changeset entries
- **Atomic releases** - version bump, changelog, tag, and deploy in one command
- **Human-readable change descriptions** - not just commit messages
- **GitHub releases** - tags can auto-create releases on GitHub

### Alternative: Simpler Approach (no changesets)
If you want the lightest solution:

```json
{
  "scripts": {
    "release": "npm version patch && npm run deploy && git push --follow-tags && git push origin main"
  }
}
```

Then manually update CHANGELOG.md or use commit messages.
