# Plan: Fix HTTP Streams Failing on GitHub Pages

## Root Cause

GitHub Pages serves over HTTPS. Modern browsers enforce mixed-content blocking — they refuse to load `http://` audio streams on an `https://` page. Six stations in `stations.js` use plain HTTP URLs, which all break in that environment.

## Affected Streams

| Station | ID | Current HTTP URL |
|---|---|---|
| Radio Caroline | 3 | `http://sc6.radiocaroline.net:8040/` |
| Radiofabrik | 8 | `http://stream.radiofabrik.at/rf_low.mp3` |
| Radio Malva | 14 | `http://radiomalva.ddns.net:8000/rmbc.ogg` |
| Ké Huelga Radio | 15 | `http://kehuelga.net:8000/radio.mp3` |
| Radio Libertaire | 17 | `http://media.radio-libertaire.org:8080/radiolib.mp3` |
| Radio Utopía | 20 | `http://streaming.radioutopia.es:8000/radio-utopia.mp3` |

None of these six streams have a publicly documented HTTPS endpoint.

## Approach

Use a small Cloudflare Worker as an HTTPS relay / reverse proxy. The Worker sits between the browser (which sees a `https://` URL) and the upstream HTTP stream server. Because the Worker serves over HTTPS, the browser never sees an `http://` URL, so mixed-content blocking does not trigger.

**Why Cloudflare Worker:**
- Zero-cost free tier (~100k req/day)
- HTTP → HTTPS edge proxy built in
- Node.js `fetch()` handles streams natively (body is satisfied by a `ReadableStream`)
- No deployment infra needed beyond `wrangler`

## Changes

### 1 — Add `proxy/radio-proxy.js` — Cloudflare Worker relay

New file. Minimal Worker: `fetch` the upstream URL, return the response with `Access-Control-Allow-Origin: *` and streaming `Content-Type`. Supports byte-range requests so the audio element can seek/resume after interruption.

```js
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url)
    const upstream = url.searchParams.get('u')
    if (!upstream) return new Response('Missing ?u= parameter', { status: 400 })
    const resp = await fetch(upstream, { headers: { 'Icy-MetaData': '1', 'User-Agent': request.headers.get('User-Agent') || 'onlypunks' } })
    return new Response(resp.body, {
      headers: {
        'Content-Type': resp.headers.get('Content-Type') || 'audio/mpeg',
        'Access-Control-Allow-Origin': '*',
        'Content-Disposition': resp.headers.get('Content-Disposition') || 'inline',
        'Cache-Control': 'no-cache',
      },
    })
  },
}
```

## Risks & Notes

- The public `radio-proxy.mrhumildad.workers.dev` subdomain must exist and be deployed **before** the GitHub Pages build, otherwise the proxied URLs will 404 or fail on the first request.
- Long-lived keep-alive connections are handled natively by the Worker's `fetch` API — Cloudflare streams the HTTP response body back to the browser without buffering the whole file.
- ICY metadata is forwarded via `Icy-MetaData: 1` header — the upstream streams must support it (most Icecast/Shoutcast servers do).
- If the user prefers not to maintain a Worker, an alternative is contacting each radio station to ask for an HTTPS stream URL.
